# 提测清单

自动化只跑了 `npm test`（类型检查、配置校验、评分、存档、备料、曲线）。没有上过真机，也没有代跑微信开发者工具。下面两段都要人来点。

## 开发者工具

1. `git pull`，在仓库根目录执行 `npm test`，应打印「颠勺王测试通过」。
2. 开发者工具选 **小游戏**，导入仓库根目录。AppID 用 `wx2ffe6f213fe9c05b`。点 **编译**。
3. 首页标题是颠勺王，副标题是「今晚六桌」。能看到通关 0/6、今日最佳、橱窗还空着。前三道可点，后三道写着未开。
4. 点番茄炒蛋。第一单会有带教：接单、备料、炒各一句。
5. 备料只点这道菜要的料。点错三次，或倒计时走完还没备齐，应失败，并能 **再做这道**，最高分不变。
6. 模拟器没有陀螺仪。炒的时候用 **手动颠勺**。提示写「颠」时再点，写「停」时别猛点。均匀上涨、糊边别满。
7. 出锅后有评级、一句科普，以及「手账在这一页」。分享按钮带「自愿」。菜册里有较长做法。
8. 番茄炒蛋、蒜蓉油麦菜、扬州炒饭都至少及格一次后，后三道应能点。鱼香看勾芡，宫保花生最后下，葱爆羊肉最赶。
9. 六道都至少及格一次，出锅页应出现「看今晚六桌」。
10. 连点右上角红印 5 次，或预览参数 `qa=1`。炒的时候底部能看到当前段和火候倍率，**火轻一点 / 火猛一点** 可调。
11. 控制台不应出现 `manifest.json.js`。清单由 `game.js` 读文件，不 `require` json。

## 真机

1. 先按 `docs/PRIVACY.md` 声明方向传感器和加速传感器，再预览。
2. 进炒之后，若声明正确，应能听到晃动；向上颠时均匀或糊边会跟着当前提示变化。画面写的是条，不是「颠了几下」。
3. 没收到数据时，字是「没收到晃动数据，先用手动颠勺」，按钮是 **再听一次**。不要去系统微信设置里找运动开关。
4. 手动颠勺和传感器规则相同。冷却感来自脉冲大约 0.3 秒，按钮不会点一下就永远发灰。
5. 静置时糊边不应因为误识别一直猛涨。故意在「停」的时候猛甩，糊边应明显涨。
6. 走完六道。分享手账、保存手账各试一次。没网时炒菜、出锅、回主页仍应能完成；分享失败只提示，不挡下一单。
7. 翻车、超时、点错料都可以免费重做同一道，而且不会把这道已经有的更高分盖掉。

葱爆羊肉时限最紧，用来看猛火，不适合当第一口教学。
