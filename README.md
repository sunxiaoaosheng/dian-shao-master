# 颠勺王

微信小游戏。玩家看到的名字是《颠勺王》。仓库目录和 `projectname` 仍是 `dian-shao-master`。`game.json` 没有游戏名字段，微信后台的小游戏名称要另外改成《颠勺王》。

把食材下进锅里，**上下左右同级、还没糊**才合成下一味，斜着不算。火候太高或锅满了这口就收。手机向上一颠，可以洗牌救场。颠出招牌菜，收进手账。

画面是灶台剪贴：撕纸边、和纸胶带、手写短句。只写厨房和食物，不写职场、工位、班表。

## 用微信开发者工具打开

1. 安装[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)，新建项目时选 **小游戏**。
2. 导入本仓库 **根目录**（这里有 `game.js`、`game.json`、`project.config.json`）。
3. AppID 用测试号 **`wx2ffe6f213fe9c05b`**。`project.config.json` 里已经写上，`isGameTourist` 为 `false`。导入时选这个 AppID，不要改成游客测试号。
4. 基础库按项目里的 `3.5.5` 即可，工具若提示升级，跟工具走。动作传感器需要较新的基础库，`2.3.0` 以上才有 `wx.startDeviceMotionListening`。
5. 模拟器可以直接玩。模拟器没有真陀螺仪，底部会出现 **手动颠勺**。
6. 改了 `src/` 之后要重新编译（见下文）。仓库里已经提交了 `dist/`，导入后不必先装依赖就能预览。

界面句子在 `src/content/copy.ts`。八句手写吐槽在 `src/content/toasts.ts`，和 `assets/manifest.json` 里的 `type.toast.*` 是同一句。剪贴规格见 `docs/COLLAGE_ART_SPEC.md`。缺的实拍图用占位 PNG 和矢量灶台，不挡开炒。

## 最短验收：试火出师再到下一火

这一段只写打开方式。本轮没有跑微信开发者工具，也没有上真机。本地先 `npm test`。

1. 检出分支 `cursor/dianshao-minigame-1f26`。
2. 开发者工具选 **小游戏**，导入仓库根目录。AppID 用 **`wx2ffe6f213fe9c05b`**。
3. 模拟器没有陀螺仪，对局里用底部 **手动颠勺**。
4. 首页应看到 **试火**，以及出师条件（合成 1 次，或撑过 20 秒）。手感按钮下面有当前档的冷却秒数。
5. 选 **家常**，点 **开炒**。
6. 出师：把两块同级食材放在上下或左右相邻的空位（斜着不算），或就在锅里撑过大约 20 秒。锅下方写着「出师 0/1·0/20秒。下一火是小火，未出师仍是试火」。凑齐之后改成「出师了。收锅后下一火是小火」。火候条过高，或有一块快糊，字会留在火候旁边。同级四向的合成规则整局都在。
7. 让火候走满，或把锅放满。结算应写 **下一锅是小火**，主按钮是 **炒下一火 · 小火**。旁边始终有 **回灶台**。
8. 再开一锅，火候名应是 **小火**，能颠的次数比试火少。
9. 若按钮是 **再试这一火 · 试火**，这口还没出师（合成 0 次，并且不到 20 秒，也没收到招牌）。
10. 免费锅用完时，还有分享次数会提示自愿分享可以再领一锅；分享次数也用完，就回灶台，明天再来。开炒按钮仍可点，会说明今天没锅了。

图没换成实拍也能走完上面这些步。激励视频和地区榜默认关着，不要为了验收去填假数据。

## 这口锅怎么打

- 点空位，把「下一手」下进锅。隔一会儿也会自己落一块。
- 上下左右挨着、等级相同、还没糊的，合成下一级。连锁会继续合。
- 放太久会糊，糊一次火候跳一截；锅本身也在慢慢升温。火候满了是 **糊锅了**。
- 要落子时没有空位：还有颠勺次数就给大约 1.5 秒，颠开了就接着炒；没有次数，或者倒计时走完，是 **锅满了**。
- 颠勺会扔掉糊块、把剩下的重新落位、火候退一截。次数用完就不能再救。
- 合成到菜谱最后一级，收一张招牌卡。两份顶级挨在一起会装盘离锅，腾位置。
- 难度：第 1 锅试火。合成 1 次，或撑过 20 秒，或收到招牌，下一锅才离开试火。否则再炒仍是试火。出师之后是小火、中火、地狱火，一档比一档赶（落子更快、糊得更急、能颠的次数更少）。结算卡会写下一锅是哪一火，按钮是「炒下一火」或「再试这一火」。

## 每天几锅、分享、广告

- 每天 **3** 锅免费，存在本地，过了当天日期就重置。
- 分享是自愿的。不分享也能打完免费锅，明天再来。按钮上写了「自愿」。
- 点分享并真正拉起面板，才加锅，每天最多 **2** 次。右上角菜单分享只带文案，不加锅。
- 微信基础库经常不告诉游戏「对方有没有收到」。真机如果 800ms 内回调失败（多半是取消），不加锅；成功回调，或者两边都不回调，视为已经自愿发起。开发者工具里一点按钮就记一次，方便验收。
- 激励视频在 `src/meta/ads.ts`。`ADS_ENABLED` 现在是关掉的，广告位 ID 也是空的，首页和结算都不放这个按钮，也不会创建 `wx.createRewardedVideoAd`，更不会发奖。TODO(owner)：流量主开通后填上 `REWARDED_AD_UNIT_ID`，把 `ADS_ENABLED` 改成 `true`。看完（`onClose` 里 `isEnded !== false`）才调用 `grantAdBonus`，关掉不算，每天最多 1 次。

## 颠勺和传感器

识别在 `src/input/gyro.ts`。平台层只做这件事：

- `wx.startDeviceMotionListening({ interval: 'game' })`
- `wx.onDeviceMotionChange`（alpha / beta / gamma）
- `wx.startAccelerometer({ interval: 'game' })` 和 `wx.onAccelerometerChange`

两路都失败、玩家拒绝权限、或开局大约 1.2 秒仍认不出重力，就留下 **手动颠勺**。开发者工具一律走这个按钮。真机传感器正常时，按钮会收起来，提示改成「握紧手机，向上颠一下」。

开局约 0.36 秒在认传感器，并判断加速度单位是 g 还是 m/s²（静置模长约 1 或约 9.8）。这段时间里的晃动不算。

要同时满足「冲量」和「200ms 内的转角」，慢转手腕、把手机放在桌上，不应该被算成颠勺。默认档是 **家常**。

| 手感 | 冲量 | 转角 | 冷却 |
| --- | --- | --- | --- |
| 轻颠 | 1.12g | 14° | 0.8 秒 |
| 家常 | 1.55g | 18° | 0.6 秒 |
| 猛火 | 2.05g | 24° | 0.4 秒 |

冷却都在 0.4–0.8 秒里。越灵敏的档，冷却越长，避免一下颠被记成两下。按钮和传感器共用这套冷却。认下时画面晃动不一样：轻颠轻，家常中，猛火重，并冒一句「轻颠 / 家常 / 猛火认下了」。火候条过了大约四分之三，或有一块熟到八成，锅上会留着糊锅提醒，不跟着短句一起消失。

常量都在 `TIERS`。真机如果静置还会跳，就把对应档的 `accelG` 调高；如果故意颠经常不认，再小幅调低。不要为了好认，把阈值降到静置噪声里。

## 本地编译和测试

```bash
npm install
npm test
```

`npm test` 会跑 `tsc`，再跑合并、糊锅、锅满、颠勺冷却、每日锅数、剪贴清单和画布冒烟。改完 `src/` 一定要再跑一次，开发者工具读的是 `dist/`。占位图用 `npm run assets` 按 `assets/manifest.json` 重写。

不要把 `dist/` 打成一个 `game.js`。模块边界要留着。
